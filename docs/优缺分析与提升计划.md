# 草料二维码安全设备看板 — 优缺分析与提升计划

> 配套文档：《复盘报告》《技术文档》
> 日期：2026-07-28

---

## 一、SWOT 分析

### Strengths（优势）
- **实时零滞后**：直连草料官方只读库，每次请求实时查询，无需同步、天然与平台一致。
- **覆盖全面**：灭火器、急救药箱、应急灯、洗眼器、压力表、消防气瓶、周期任务全覆盖，含效期/维修/报废预警。
- **稳定性达标**：前端 `allSettled`+超时兜底、no-cache、dbStatus 监控，已多次线上复测通过。
- **轻量易维护部署**：Express 单文件 + 原生前端，无复杂构建，Railway 一键部署。

### Weaknesses（劣势）
- **单文件巨石前端**：`index.html` 已超千行，所有图表/逻辑堆在一个文件，后续改一处易牵一发动全身。
- **无查询缓存**：每个请求实时打 RDS，高频刷新有性能损耗与官方库限流风险。
- **无访问控制**：拿到 URL 即可读全部设备数据，存在信息暴露风险。
- **无自动化测试/CI**：回归靠人工线上验证，改 bug 易引入新问题（本次就发生过 JS 废代码致整段失效）。
- **部署依赖 GitHub**：本环境 git 推送受网络限制，需走 API 兜底，链路脆弱。

### Opportunities（机会）
- **告警推送**：临期/报废/超期自动推企业微信、钉钉、邮件，从"人去看"变"主动提醒"。
- **报表导出**：一键导出 Excel/PDF，满足安全台账留痕与合规审计。
- **趋势预测**：基于历史报废量做年度预测，辅助预算与采购。
- **移动端适配**：现场巡检用手机即可看设备状态与预警。
- **多组织/多账号**：支持多家工厂或不同草料账号切换。

### Threats（威胁）
- **草料官方库结构变更**：字段改名/表拆分会直接打挂查询（当前无容错）。
- **只读账号失效/限流**：账号过期或被限流会让看板全盲。
- **Railway 免费额度用尽**：云端服务中断。
- **数据口径变化**：草料平台规则调整导致"当前值"口径变化。

## 二、可提升计划（按优先级）

### P0 — 保稳定、补安全（建议 1~2 周内）
1. ✅ **查询缓存层（已完成 2026-07-28）**
   - 进程内内存缓存（Map 实现，零依赖），`query()` 默认对统计接口缓存 60s（`CACHE_TTL` 可调，0=关闭）；`/api/cache/stats` 查看命中、`/api/cache/clear` 手动清空；健康检查不缓存。
   - 收益：降低 RDS 压力与官方库限流风险，页面响应更快。
2. ✅ **基础访问控制（已完成 2026-07-28）**
   - 访问令牌（`?token=` 或请求头 `x-api-token` / `Authorization: Bearer`）+ 可选 IP 白名单（`ALLOWED_IPS`）；默认令牌 `cli-dash-2026`，生产请改 `ACCESS_TOKEN` 环境变量；`/api/health` 免鉴权便于监控。
   - 收益：避免设备数据对外裸奔。
3. ✅ **前端组件化拆分（已完成 2026-07-27→2026-07-28 收口）**
   - `index.html` 拆分为 `public/js/core.js`、`sections.js`、`app.js` 三个外链脚本（按"全局工具/插件/令牌 / 各模块 loader / 调度初始化"职责切分），任一处语法错误不再拖垮整页。
   - 收益：降低"改一处崩全局"风险，提升可维护性。
4. ✅ **关键查询容错（已完成 2026-07-28）**
   - `existingColumns()` + `safeSelect()` 先探测 `information_schema` 实际列，缺失列降级输出 `NULL` 而非整接口 500；已应用于 first-aid/expiry、灭火器 maintenance/scrap/analysis 四大主数据接口。
   - 收益：草料结构微调时看板不崩。

### P1 — 提效率、加能力（建议 1~2 月内）
5. **CI / 自动冒烟**
   - 推送即跑 `node --check` + 启动服务跑 3~5 个核心 API 冒烟，失败拦截合并。
   - 收益：杜绝"整段 JS 失效""接口 500"类回归。
6. **告警主动推送**
   - 临期/报废/超期自动推企业微信/钉钉，支持阈值配置。
   - 收益：安全预警从被动查看转主动触达。
7. **报表导出**
   - 明细表/预警清单导出 Excel/PDF，支持按日期切片导出。
   - 收益：满足安全台账合规留痕。

### P2 — 扩场景、强体验（后续规划）
8. **移动端响应式适配**，现场巡检友好。
9. **趋势预测**（如灭火器年度报废量预测），辅助采购预算。
10. **多组织/多账号**支持，适配集团或多厂。
11. **部署去 GitHub 依赖**：评估不依赖 GitHub 的部署方式（如直接打包镜像/静态服务），降低本环境推送限制影响。

## 三、关于"全程免费"的说明

用户问"全程免费吧？"——就本项目实际涉及的成本点澄清如下（以当前实情为准，不含任何承诺）：

| 环节 | 是否免费 | 说明 |
|------|----------|------|
| 看板代码 / 文档（本助手产出） | 是 | 代码与文档本身无费用 |
| GitHub 仓库 | 免费 | 公开仓库免费；私有仓库也在免费额度内 |
| Railway 部署 | **有免费额度** | Railway 提供免费层（含部署额度/休眠策略），超出后按用量计费；当前看板体量小，基本在免费层 |
| 草料官方数据库 | **取决于你的草料套餐** | 官方数据库（只读副本）是草料平台能力，是否包含在你的订阅中由草料套餐决定，并非本项目额外收费 |
| 阿里云 RDS | 由草料承担 | 该只读库是草料侧资源，用户不直接付费给云厂商 |

**结论**：本项目"开发 + 托管 + 代码"层面基本处于各家免费额度内，不额外产生费用；唯一可能与"套餐/额度"挂钩的是**草料官方数据库的开通资格**（看你的草料订阅）与 **Railway 免费额度是否被用尽**。若担心 Railway 额度，可随时迁移到其它免费/低成本托管（如 CloudStudio、Vercel、或自托管），后端代码无需改动。

## 四、一句话建议

先把 **P0（缓存 + 鉴权 + 前端拆分 + 查询容错）** 做了，看板的稳健性与安全性会有质的提升；再视业务需要上 P1 的告警推送与报表导出，价值最直观。
