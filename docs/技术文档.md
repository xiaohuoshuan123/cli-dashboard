## 1. 架构总览

```
[浏览器 / 任意设备]
        │  HTTPS  GET /api/...
        ▼
[Railway 托管的 Express 服务]   ← 也可本地 node server.js (:3000)
        │  mysql2 连接池  SELECT ...
        ▼
[草料官方 MySQL 只读副本 (阿里云 RDS)]
  rm-bp1m4fy8d66u3c6xmbo.mysql.rds.aliyuncs.com:3306
  database / user: cli_44608921  (只读账号)
```

**核心原则**：看板**不存储、不同步**草料数据，而是**每次请求实时查询**官方库。因此看板与草料平台天然实时一致，无同步滞后。（`C:\...\cli_data` 仅为首次探索导出的静态 JSON 快照，看板不读取。）

## 3. 数据模型（核心认知）

草料官方库表分两类，分析"当前状态"务必认准 **template 主数据表**：

| 类型 | 命名 | 含义 | 用途 |
|------|------|------|------|
| 子码主数据表 | `template_codeinfo_<id>` | "码"的**当前字段值**（草料前台展示值） | 分析当前状态、效期、明细 |
| 表单提交日志 | `table_d<id>` | 表单历史提交记录 | 趋势统计（历史流水量） |
| 基础表 | `base_*` | 码信息、账号、任务日志等 | 概览、排名 |
| 周期任务 | `cycle_plan` / `cycle_task` / `cycle_task_instance` | 计划/任务/执行实例 | 计划执行、超期、到期 |
| 设备状态 | `code_state` | 压力表、消防气瓶等状态 | 状态分布 |

**已验证的关键字段映射（节选）**：

- 急救药箱（主数据 `template_codeinfo_d25`）：
  - 工段 `工段名称_3333285`、管理人 `管理人_3333286`、位置 `存放位置_3333288`、子码编号 `子码编号`
  - 药品有效期：`碘伏有效期_3398001` / `创可贴有效期_3397997` / `棉签有效期_3398000` / `双氧水有效期_3398002` / `藿香正气水有效期_3398038` 等
- 灭火器（主数据 `template_codeinfo_d10`）：
  - 名称 `消防器材名称_3170252`、点检人 `点检人_3170286`、责任部门 `责任部门_81035291262977`、位置 `所在位置_3170087`、编号 `编号_3170086`、生产厂家 `生产厂家_3170090`
  - 下次维修再充装 `下次维修再充装日期_3170398`、钢瓶强制报废 `钢瓶强制报废日期_3170397`
- 设备状态（`code_state`）：`压力表状态_3947037`、`消防气瓶状态_8880647`

**全表单汇总视图 `base_table_data`**（`/api/records/latest` 来源，共 8853 行）：
- 实测 = 12 张 `table_dXX` 表单历史表的完整 UNION（行数 = 各表之和），是"每提交一条记一行"的**全量提交历史**，并非"每码只留最新一条"；统计"每人提交总次数"口径准确（发奖依据）。
- 含 12 列：`record_id` / `code_id` / `tpl_code_id` / **`码名称`** / `tpl_id` / `记录单名称` / `记录时间` / `记录人` / `member_id` / `auth_id` / `状态` / `记录编号`。**最新提交记录直接 SELECT `码名称` 即可，无需 JOIN**（阶段 18 确认）。

**计划执行表 `code_task_log`**（`/api/tasks/*` 来源）：
- 字段：`log_id`/`task_id`/`计划名称`/`code_id`(可关联码)/`开始时间`/`执行时间`/`截止时间`/`状态`/`是否过滤`/`变更方式`/`来源`/`来源记录结果`。
- 本表**无码名称**，需 `LEFT JOIN base_codeinfo`（含 `码名称`/`模板名称`/`目录`，以 `code_id` 为 PK，775 行）补全；实测命中 7782/7790。
- **已识别的草料数据质量问题**：`灭火器每月点检计划` 名下误挂 **19 个应急灯码**（对应 38 条执行日志，非 19 个不同码各 38 条），导致 `GROUP_CONCAT` 列出"消防应急灯检查"使目录显示错乱。看板改为显示**占比最高的主目录 + 含其他N类**缓解，根因需在草料后台修正（看板只读账号无法回写）。

**最新周期过滤实现**（避免历史周期干扰）：
```sql
-- deadline / overdue 均按 plan 取 MAX(end_time) 的最新实例
WHERE (i.plan_id, i.end_time) IN (
  SELECT plan_id, MAX(end_time) FROM cycle_task_instance GROUP BY plan_id
)
```

## 5. 关键实现点

### 5.1 实时查询
每个 API 通过 `mysql.createPool()` 连接池执行 `SELECT`，**无任何中间缓存/同步步骤**，所以数据永远是最新的。

### 5.2 日期兼容与防时区偏移
草料日期格式有两种：`YYYY/MM/DD` 与 `YYYY年MM月DD日`。解析后用**本地年月日**拼 ISO，避免 `new Date('2027/03/01')` 被当 UTC 导致显示偏移一天。

### 5.3 饼图/环形图数据标签
自定义全局 Chart.js 插件 `pieLabelPlugin`（id `pieLabels`）：
- `afterDatasetsDraw` 钩子中，对每片扇区中心绘制 **数值 + 百分比**；
- 按扇区背景亮度自动选黑/白字，保证可读性；
- `Chart.register(pieLabelPlugin)` 全局注册，所有 `pie`/`doughnut` 图表生效。

### 5.4 强制报废预警
`/api/fire-extinguisher/scrap` 读 `钢瓶强制报废日期_3170397`，按剩余天数分级（如 ≤0 已报废、≤30 临期、≤365 一年内），前端按责任部门出柱状图 + 明细表，并提供天数筛选。

### 5.5 前端健壮性
- `fetchAPI()` 用 `AbortController` 设 14s 超时，单个接口卡死不影响整体；
- `loadAllData()` 用 `Promise.allSettled` + `finally` 兜底，确保 loading 必定清除（根治"一直加载中"）；
- 前端 `index.html` 加 `Cache-Control: no-cache`，避免重部署后浏览器加载旧版。

### 5.6 导出 Excel 修复 + 原始库表导出（阶段 17）
- **A1 单元格根因修复**：`exportTable()` 原 `getElementById` 拿到 id 挂在 `<tbody>` 的元素，克隆后 `outerHTML` 只剩 `<tbody>` 无 `<table>` 包裹，Excel 无法识别结构→全部数据挤进 A1。改为 `el.closest('table')` 取真正的 `<table>` 根；`downloadExcelHtml` 给 `<table>` 补 `border="1"` 并 `escapeHtml()` 转义 `<`/`&`，防原始数据破坏表格。
- **原始库表导出**：`/api/devices/raw?type=extinguisher|light` 用 `information_schema` 取 `template_codeinfo_d10`(灭火器 533 行 15 列)/`d15`(应急灯 83 行 10 列) **真实列序原值不加工**，返回 `{table,columns,rows}`；前端 `exportRawDevice(type)` 从 columns+rows 拼干净 table 导出，直接对应草料原始库表，可对账。

### 5.7 智能图表选型（阶段 18）
灭火器/应急灯多维分析按**分类数动态选型**：`const useDoughnut = labels.length <= 6;` —— ≤6 类用 `doughnut` 环形饼图（右侧图例），>6 类用 `bar` 且 `indexAxis:'y'`（横向条形，避免标签拥挤）；应急灯用 12 色调色板。

### 5.8 月度趋势数值标签（阶段 18）
`loadMonthlyTrend` 注册自研 `valLabel` 插件（`afterDatasetsDraw` 在每个数据点上方 `ctx.fillText` 绘制数值），不依赖任何 CDN 插件。

### 5.9 顶部健康提示统一框（阶段 18）
`loadAlerts` 把多条告警（压力表超期、灭火器临期、应急灯异常等）统一收进一个 `.card`（左边框蓝色），标题「🩺 系统健康运行提醒」，内部 `.health-alert-list` 逐条 `alert`；新增告警 push 同一数组，不再散落多处。

### 5.10 全局表格列宽自适应（阶段 18）
所有 `th, td { white-space:nowrap }` 防字段挤成 2 行，超宽内容靠外层 `.table-wrap` 横向滚动；**唯一例外**急救药箱"药品明细"列特加 `.med-cell { white-space:normal }` 允许换行（多个药品 chip 堆叠必须换行）。新增全局表格默认套此约定。

### 5.11 计划执行明细"主目录"显示（阶段 18）
`/api/tasks/details` 按 `(计划名称, b.目录, b.模板名称)` 分组，Node 端按计划名累加状态计数、取**占比最高的目录/模板为主目录**，多类时标"含其他N类"（如"灭火器检查（含其他1类）"）。解决草料把 19 个应急灯码误挂到灭火器计划导致目录并列显示的误导。

## 7. 已知约束

- 只读账号，无法回写草料数据（符合预期，安全）。
- 统计/明细接口已加 **60s 内存缓存**（`CACHE_TTL` 环境变量可调，0=关闭），降低 RDS 压力；实时性要求高的字段仍直连查库。
- 前端为单文件，未做组件化（维护性见提升计划）。
- 访问控制：令牌鉴权（默认 `cli-dash-2026`，可用 `ACCESS_TOKEN` 覆盖；可选 `ALLOWED_IPS` IP 白名单）。**令牌通过 `x-api-token` 请求头（或 `Authorization: Bearer`）传输，不再拼在 URL 中**，避免落入服务器访问日志 / 浏览器历史。另加**基础限流**（零依赖，按 IP 固定窗口，`RATE_LIMIT`/`RATE_WINDOW` 默认 120 次/60 秒，超阈值返回 429）。
- 草料库存在**数据质量问题**：已识别"19 个消防应急灯码被误挂到灭火器每月点检计划"（对应 38 条执行日志），导致计划目录显示错乱。看板已用"主目录+含其他N类"缓解显示误导，但**根因属草料建码/分配计划时的数据错误，看板只读账号无法回写**，须到草料后台纠正（验证脚本见 `scripts/verify-plan-time.js` / `scripts/verify-plan-dirs.js`）。
- 后端保留 6 个已删区块的"〔死代码〕"端点（见 §4 标注），功能以活跃端点为准，后续可清理减小表面积。
